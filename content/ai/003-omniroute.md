## 什么是路由策略？

路由策略决定 OmniRoute 如何在多个 AI 提供商之间分配请求。不同的策略适用于不同的场景。

```
请求进来 → Router → 选择哪个 Provider？
```

OmniRoute 提供 17 种路由策略，从简单的「顺序使用」到复杂的「智能评分」。

---

## 推荐策略（新手首选）

### cost-optimized — 成本优先

自动选择当前最便宜的可用模型，节省成本。

> 适合：日常使用、预算有限

### lkgp — 记忆优先

Last-Known-Good-Path，记住上次成功的提供商，优先使用。

> 适合：需要稳定输出的场景

### auto — 智能自动

9 因素实时评分，综合考虑健康度、配额、成本、延迟、成功率等。

> 适合：大多数场景（推荐使用）

---

## 策略详解

### 1. priority（优先级）

按固定顺序使用提供商列表，每个用完后再切换下一个。

### 2. fill-first（填满优先）

尽量填满每个提供商的配额，用完后再移动到下一个。

### 3. weighted（加权随机）

按配置的比例随机分配请求。例如 A 60%、B 30%、C 10%。

### 4. round-robin（轮询）

轮流使用每个提供商，公平分配负载。

### 5. p2c（两次随机选择）

随机选两个，再选其中负载较低的。比纯随机更均衡。

### 6. least-used（最小负载）

选择当前请求数最少的提供商。

### 7. random（去重随机）

均匀随机选择，同一请求不会重复发往同一提供商。

### 8. strict-random（严格随机）

纯随机选择，可能重复发往同一提供商。

### 9. cost-optimized（成本优化）

根据实时目录定价，选择最便宜的模型。

### 10. headroom（余量优先）

选择配额剩余最多的提供商，最大化利用。

### 11. reset-window（重置窗口）

优先使用即将重置的配额（快过期的先用）。

### 12. reset-aware（重置感知）

按配额重置时间排名，短窗口优先（避免等待）。

### 13. context-relay（上下文中继）

切换提供商时传递上下文，适合长对话。

### 14. context-optimized（上下文优化）

根据当前上下文大小选择最合适的提供商。

### 15. lkgp（上次成功路径）

记住上次成功的提供商，粘性使用，出错才切换。

### 16. auto（自动评分）

综合 9 个因素实时评分，动态选择最优。

### 17. fusion（融合）

同时发往多个模型，由评判模型合成最优答案。

---

## 快速选择指南

| 场景           | 推荐策略                               |
| -------------- | -------------------------------------- |
| 日常开发       | `auto` 或 `cost-optimized`             |
| 需要稳定输出   | `lkgp`                                 |
| 团队共享配额   | `weighted` 或 `round-robin`            |
| 测试多个模型   | `random` 或 `fusion`                   |
| 最大化免费额度 | `headroom` 或 `reset-window`           |
| 长对话         | `context-relay` 或 `context-optimized` |

---

## 如何配置策略

在 OmniRoute Dashboard 或配置文件中设置：

```yaml
# 使用 auto 策略（最简单）
model: auto

# 使用成本优先策略
model: auto/cheap

# 使用编程优化策略
model: auto/coding

# 自定义 Combo + 指定策略
# 在配置文件中定义 combo 和 strategy
```
