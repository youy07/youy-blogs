让 AI "读懂"你的私有资料——从零搭建专属问答系统

⏱ 预计时间：15-20 分钟

🎯 本课目标

在 Dify 里创建一个知识库，上传一份真实文档，构建一个能准确回答文档内容问题的 AI 问答应用。

## 一、RAG 是什么？（先搞懂原理）

RAG = **Retrieval-Augmented Generation**（检索增强生成）。

简单说：大模型虽然聪明，但它**不知道你公司的内部资料**。RAG 就是给大模型配了一个"资料查阅员"——

```
┌─────────────────────────────────────────────────────────┐
│                   用户提问                               │
│              "公司年假怎么申请？"                         │
└────────────────────┬────────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────────┐
│           ① 向量检索（查资料）                           │
│   把问题转成向量 → 在知识库里找最相关的段落                │
│   → 找到：《员工手册》第 8 章"年假申请流程"              │
└────────────────────┬────────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────────┐
│           ② 增强生成（喂给大模型）                        │
│   提示词：                                               │
│   "根据以下资料回答问题：【资料内容】...                   │
│   用户问题：公司年假怎么申请？"                           │
└────────────────────┬────────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────────┐
│           ③ AI 回答（有依据，可追溯）                     │
│   "根据《员工手册》第 8 章，年假申请需：               │
│    1. 提前 7 天在 OA 提交申请...                       │
│    📎 来源：《员工手册》第 8 章"                       │
└─────────────────────────────────────────────────────────┘
    
```

RAG 的核心流程：检索相关资料 → 喂给大模型 → 生成有依据的回答

✅ RAG 的核心价值

- **知识实时更新**：上传新文档，AI 立刻"知道"新内容（无需重新训练模型）
- **回答有依据**：每个回答都附带来源，可追溯、可验证
- **数据安全**：资料存在你自己的服务器，不会泄露给模型厂商
- **成本低**：比 Fine-tuning（微调）便宜 100 倍，效果往往更好

## 二、准备你的第一份文档

在动手之前，先准备一份文档用来测试。建议用你真实业务中的文件，这样学完立刻能用。

📄 推荐测试文档类型

- **员工手册 / 制度文件**：测试"政策问答"场景
- **产品说明书 / FAQ**：测试"客户自助服务"场景
- **操作手册 / SOP**：测试"内部培训"场景
- **合同模板**：测试"文档分析"场景

**支持的文件格式：**

.pdf ✅ 推荐.docx ✅ 推荐.txt ✅ 推荐.md ✅ 推荐.csv ⚠️ 需预处理.xlsx ⚠️ 需预处理.jpg/.png ⚠️ 需 OCR

**⚠️ 文档质量直接影响回答效果！**
扫描版 PDF（图片格式）需要先 OCR 识别文字；表格复杂的 Excel 建议先转成 CSV 或 TXT。

## 三、创建知识库（ step by step）

**1** 

#### 进入知识库页面

Dify 控制台 → 顶部导航栏 → **知识库** → 点击"创建知识库"

**2** 

#### 选择数据源

有三个选项：

- **导入已有文本**：直接上传文件（最常用）
- **同步自网页**：输入 URL，自动抓取网页内容（适合帮助中心）
- **同步自 Notion / 飞书**：从协作文档同步（需授权）

→ 选择"导入已有文本"，上传你的测试文档

**3** 

#### 配置文本分段（关键！）

这是 RAG 效果好坏的**最关键一步**。Dify 会把文档切成一个个"段落（Chunk）"，检索时找最相关的段落。

| 分段方式       | 适用场景               | 推荐设置                                |
| :------------- | :--------------------- | :-------------------------------------- |
| **自动分段**   | 快速测试，文档结构清晰 | 默认即可，段落大小 500 字符             |
| **自定义分段** | 精确控制，文档复杂     | 段落大小 300-800 字符，重叠 50-100 字符 |
| **父子分段**   | 长文档（手册/报告）    | 父段落 2000 字符，子段落 500 字符       |

**💡 分段策略建议**
\- 文档有标题结构（如员工手册有章节）：用**自动分段**
\- 文档是连续文本（如合同）：用**自定义分段**，段落小一点（300-500 字符）
\- 文档很长（如 50 页产品手册）：用**父子分段**，检索更精准

**4** 

#### 选择 Embedding 模型

选择你在第 3 课配置的 Embedding 模型（如 `bge-m3` 或 `text-embedding-3-small`）。

点击"保存并处理"，Dify 开始把文档向量化（需要几分钟，取决于文档大小）。

**5** 

#### 等待处理完成

处理状态从"处理中"变成"可用"后，知识库就准备好了。

点击知识库名称，可以看到：

- 文档列表（已上传的文档）
- 分段预览（可以查看每个段落的内容）
- 召回测试（输入问题，看能不能找到相关段落）

## 四、测试知识库召回效果

在知识库页面，有一个很重要的功能——**召回测试**。这是调优 RAG 效果的核心工具。

🔍 召回测试怎么用？

1. 在知识库页面 → 点击"召回测试"标签
2. 输入一个你文档里有的问题（如"年假怎么申请？"）
3. 观察返回的顶部段落是否相关
4. 如果返回的内容不相关 → 调整分段策略 → 重新处理

**⚠️ 召回测试没结果或结果不相关？**
常见原因：① 分段太大/太小 ② 问题措辞和文档差异太大 ③ Embedding 模型效果差（建议换 bge-m3 或 text-embedding-3-small）

## 进阶：Rerank 重排序与混合检索（Hybrid Search）

前面学到的基础 RAG 流程是"检索 → 生成"，但实际生产环境中还有两个关键优化技术：**混合检索**和**Rerank 重排序**。

### 什么是混合检索（Hybrid Search）？

Dify 支持两种检索方式同时工作：

🔍 两种检索方式

- **语义检索（向量检索）**：用 Embedding 模型把文本转成向量，靠语义相似度匹配。适合自然语言问题，比如"怎么请假？"能匹配到"请假流程"。默认模式。
- **关键词检索（BM25）**：传统的倒排索引，靠关键词匹配。适合精确查找，比如"产品编号 SKU-1234"或"2026年考勤制度"。不会产生语义混淆。

✅ 什么时候开混合检索？

- **文档含大量专业编号/代码**：产品编号、订单号、法条编号——这些语义模型"看不懂"，必须靠关键词
- **用户问题偏精确查询**：如"我的订单状态是什么？"而非"推荐类似产品"
- **语料和专业术语较冷门**：Embedding 模型可能对这些词的语义理解偏差大

**配置方法**：知识库编辑页面 → 检索设置 → 勾选"启用混合检索"（Dify 会自动合并两种检索结果并以语义权重排序）。

**💡 混合检索不是免费的**：开启后会消耗额外算力（BM25 索引构建 + 双路检索），检索延迟略有增加，但通常可接受。

### 什么是 Rerank（重排序）？

基础 RAG 流程中，向量检索返回 Top K 个结果后直接喂给 LLM。但向量相似度 ≠ 语义相关性，排名靠前的不一定是真正最相关的。

🔄 Rerank 做了什么

在"检索"和"生成"之间插入一个**精排环节**：

1. **粗召回**（向量/混合检索）：从全量文档中召回 Top 20-50 个候选段落
2. **精排序**（Rerank 模型）：对每个候选项计算与问题的真实相关性分数 → 取 Top 3-5
3. **增强生成**：只把最相关的 TOP 片段喂给 LLM

✅ Rerank 能解决什么问题

- **检索结果不精确**：向量召回的前几条虽然"像"，但实际不回答问题 → Rerank 重新排序后，真正有用的片段会被推到前面
- **上下文过载**：如果你设置 Top K=10，可能一半是噪音 → 先用向量召 Top 30 再过 Rerank 取 Top 3，LLM 只收到最精华的内容

### 如何在 Dify 中配置 Rerank？

**1** 

#### 接入 Rerank 模型

设置 → 模型供应商 → 添加 Rerank 模型：

- **推荐本地部署**（免费）：Ollama 运行 `bge-reranker-v2-m3`，中文效果好
- **推荐云服务**（付费）：Cohere Rerank（`rerank-v3.5`），支持多语言，API 稳定
- **其他选择**：通义千问 Rerank、Jina Reranker，直接在对应供应商页面添加

**2** 

#### 在知识库中启用 Rerank

知识库编辑页面 → **检索设置** → 打开 Rerank 开关 → 选择刚配置的 Rerank 模型

**3** 

#### 验证效果

保存后用**召回测试**对比开关 Rerank 前后的结果差异。你应该看到不相关的片段被重新排到了后面。

**⚠️ 什么时候不需要 Rerank？**
如果你的知识库文档结构清晰、向量检索效果已经很好（召回测试准确率 > 90%），Rerank 带来的提升有限。
Rerank 模型每次查询都会调用，**有额外的 API 费用或 GPU 消耗**，需要权衡投入产出比。

### 混合检索 + Rerank 的最佳组合

生产环境的推荐配置：

```
# Dify 知识库检索设置（生产推荐） Top K（粗召回）= 20          # 召回量足够大，给 Rerank 筛选空间 Rerank Top K = 3-5           # 精排后只取最相关的 相似度阈值 = 0.5              # 阈值设低一点，粗召回不遗漏 检索方式 = 混合检索             # BM25 + 向量并行 Rerank 模型 = Cohere / bge-reranker  # 精排保证质量
```

这套配置的特点是：**粗召回不遗不漏，精排去噪去重**。对大多数企业知识库场景效果都很好。

## 六、用知识库构建一个问答应用

知识库创建好了，现在把它变成一个能用的 AI 应用：

**1** 

#### 创建聊天助手应用

工作台 → 创建应用 → 选择"聊天助手" → 填写应用名称

**2** 

#### 关联知识库

在应用编辑页面：

- 右侧 → 上下文 → 点击"+"
- 选择你刚创建的知识库
- 设置"召回设置"：
  - **Top K**：返回最相关的几个段落（推荐 3-5）
  - **相似度阈值**：低于此分数的段落不返回（推荐 0.7）

**3** 

#### 编写提示词（Prompt）

在"提示词"框里写清楚 AI 的行为规范，例如：

```
# 角色 你是一个公司内部知识库助手，负责回答员工关于公司制度和流程的问题。 # 要求 - 只根据提供的上下文资料回答问题，不要使用你的通用知识 - 如果资料里没有相关信息，明确告诉用户"该问题在现有资料中未找到相关信息" - 回答时注明信息来源（如"根据《员工手册》第 X 章"） - 语气专业、简洁 # 上下文 {context} # 用户问题 {query}
```

**💡 提示词技巧**：`{context}` 和 `{query}` 是 Dify 的变量，会自动替换为知识库内容和用户问题，**不要改这两个变量的名字**。

**4** 

#### 预览测试

点击右上角"预览"，在右侧对话框里输入问题，看 AI 是否能准确回答并附带来源。

**5** 

#### 发布应用

测试满意后，点击"发布"→"更新"→"访问 API 密钥"获取 API 地址，或点击"嵌入网站"获取嵌入代码。

## 七、知识库最佳实践

✅ 文档准备建议

- **拆分大文档**：一本 100 页的手册，建议按章节拆成多个文档上传（检索更精准）
- **清理格式**：删除页眉页脚、乱码、特殊字符，减少噪音
- **保留标题结构**：有标题的文档分段效果远好于纯文本
- **定期更新**：制度有变动时，重新上传最新版文档（可设置自动同步）

⚠️ 常见效果问题 & 解决方案

- **回答不相关** → 调低相似度阈值（0.5-0.7），或调整分段策略
- **回答太短/不完整** → 增大 Top K（5-8），或调大段落大小
- **幻觉（编造内容）** → 严格提示词，要求"只根据上下文回答"
- **检索不到** → 检查 Embedding 模型是否正常，召回测试验证

## 八、本节课重点回顾

- ✅ RAG = 检索相关资料 + 喂给大模型 + 生成有依据的回答
- ✅ 创建知识库：导入文档 → 配置分段 → 选择 Embedding 模型 → 向量化
- ✅ 分段策略是关键：自动分段（快速）/ 自定义（精确）/ 父子（长文档）；进阶：混合检索 + Rerank 精排
- ✅ 召回测试是调优核心工具，先在知识库里测好再搭应用
- ✅ 构建问答应用：创建聊天助手 → 关联知识库 → 写提示词 → 发布
- ✅ 提示词里用 `{context}` 和 `{query}` 变量引用知识库内容
